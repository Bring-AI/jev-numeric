# BipedalWalker prompt recovery — live evidence and audit

No live episode in this directory has yet been certified as terrain-finished. `manifest.json` is the current attempt ledger; running episodes are listed as incomplete. Only an episode's independently replayed `audit.json` with `replay_terrain_finished: true` establishes success.

All full episodes use real `typesafe/jev-1.13-20260917` /systemone choice responses for every motor, with K=20, physical grid [-1,1), resolution0.005 and final lower endpoint execution. No trained policy, external motor controller, motor fallback, hand-picked executable action, environment modification, starting-state modification, or alternate success criterion is used. Normal Gymnasium1.3.0 BipedalWalker-v3 terrain and 1600-frame horizon remain intact. Original seeds7/19 are retained.

The original qualitative prompts confused joint angle goals with motor torque. Initial probes in `probes-*.json*` show that per-question literal PD expressions often improve signs, while errors in decimal magnitude, arithmetic sums and saturation remain. Probe results are API calls on archived observations, not game episodes.

`v2_literal` through `v5_tuned_verbal` used hold5 and a simplified six-state gait chosen by Jev. This simplified gait permits one transition per decision. It does not reproduce the stock reference's chained SWING→LOWER→PUSH initialization and fails offline as well. These runs must not be described as faithful executions of the public heuristic.

`v6_reference` and `v7_reference_cases` changed hold5→hold1 and added model-selected joint angle goals and model-selected knee memory. Their parallel goal/planning questions often conflict, despite a correct returned phase. `v8_focused_reference` specialized each planning question around current model memory, reducing planning mistakes; remaining torque mistakes and backward drift caused left-boundary termination.

`v9_sequential` obtains one Jev gait-case choice before subsequent questions. Six action cases encode SWING, LOWER, LOWER_PUSH, LOWER_PUSH_SWITCH, PUSH and PUSH_SWITCH for the current model-selected moving leg. These preserve the public heuristic's sequential IF logic and retain lowering hip goals during same-step push. A fixed disclosed template maps the chosen gait case to joint ANGLE goals. Jev then selects numeric support-knee memory in two calls. Finally Jev directly selects all four MOTOR TORQUES in two K20 refinements. Python only renders raw measurements and chosen goal values into the disclosed PD expressions, decodes chosen intervals and executes their lower endpoints. There are five API calls per one physics frame. Hold1 and the explicit planning protocol mean this is not a prompt-only controlled comparison with the original hold5 run.

`v10_rounded` kept the sequential protocol and rounded prompt measurements to3decimals while preserving raw logs. This did not improve the tested rollout.

`diagnostic*.json`, `diagnostic*.py`, and `search*.py` are offline Python reference/controller analyses and are NEVER Jev scores. In one diagnostic, the public heuristic at hold1 with1.1 output gain completes seed7 at1578frames with reward312.62. That proves the unchanged environment can be completed by that controller; it is not a model result. The gain sweep and unsuccessful hold5/controller sweeps are fully retained.

Each completed run has `actions.jsonl`, `api-records.jsonl`, `api-records.json`, source snapshots, rules, a full replay video, preview GIF and summary. `audit.py` independently reconstructs every motor from the exact API choices, replays the episode from the same seed, checks raw observations/reward/termination and success, and hashes the core artifacts. It never substitutes a controller action. Run it to refresh `audit.json` and `manifest.json` after live episodes complete.

`v12_fall_extension` added a prompt-only emergency rule asking Jev for maximum positive knee torque if upward torso velocity was below−0.12. It fell after224frames. `v13_phase_predicates` put each full raw-value logical predicate in the phase choice itself and restricted candidates by the previous model phase; it fell after128frames.

`v14_inequality` retains dynamic knee memory but restates motor options as complete arithmetic inequalities, with extreme intervals extending outward to express saturation. `v15_fixed0_inequality` additionally replaces the fragile dynamic knee memory with a disclosed fixed support-knee ANGLE0.0. Its only intermediate output is the model gait case; motor selection still uses K20,0.005, two refinements. It needs3API calls per physics frame. The fixed-angle policy was independently verified offline to complete seeds7/19, but such offline completion is not a model success.

`v16_fixed0_direct` is the missing comparison with fixed support-angle0.0 and direct motor interval prompts (instead of repeating inequality expressions). `v17_simple_coefficients` additionally uses simpler fixed feedback coefficients: hip error0.5, knee error2, joint-speed damping0.15, torso-angle balance0.5, torso-rotation balance1, vertical knee damping8. These are disclosed prompt policy changes; no desired motor command is precomputed or substituted.
